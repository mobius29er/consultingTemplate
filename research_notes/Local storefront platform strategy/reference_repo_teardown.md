Source: local files in `/home/user/catholicjoe` (shallow clone of github.com/mobius29er/CatholicJoe; single visible commit `4070d44 2026-10-02 "Merge pull request #1 from mobius29er/codex/accessibility-seo-performance"`). All paths are relative to that directory unless absolute. `file:L12-L20` means lines 12–20. No web sources were used; no files in the reference repo were modified. Secret **names** are listed; no secret values appear in the repo's tracked files and none are reproduced here.

**Differences from the older `catholicjoesuperhero` repo (for context only):** the old version used Resend over REST for email, a D1 double-opt-in newsletter, a single env `price_` ID with a Stripe shipping rate, manual-only fulfillment and one admin allowlist. The current repo replaced those with Cloudflare's native `send_email` binding, Mailchimp hosted forms, a Stripe Product whose default Price is read live, ShipStation V2 rate quotes + order export + tracking ingestion with a cron trigger, a revocable "developer" admin role, a custom Worker entry with canonical-host redirects, and migrations 0003–0007.

Top-line facts:

- Stack: **Astro 7.3.4 + @astrojs/cloudflare 14.3.3 on Cloudflare Workers, D1, better-auth 1.7.5 (email/password + TOTP), Stripe 22.6.2, Cloudflare Email Sending (`EMAIL` binding), ShipStation platform V2 API, Mailchimp hosted signup form** ([package.json:L18-L37](/home/user/catholicjoe/package.json), [wrangler.jsonc:L15](/home/user/catholicjoe/wrangler.jsonc), [src/lib/server/shipping.ts:L82](/home/user/catholicjoe/src/lib/server/shipping.ts), [src/data/newsletter.ts:L2-L4](/home/user/catholicjoe/src/data/newsletter.ts)).
- **ShipStation is genuinely integrated** in three places: live USPS rate quotes at checkout, paid-order export as an unlabelled shipment + sales order, and inbound label/tracking webhooks plus a 5-minute cron that pulls canonical label/track data back into `orders`. Labels are still purchased by the owner inside ShipStation.
- **Mailchimp is integrated as a hosted form handoff only**: the site's forms POST directly to Mailchimp's `list-manage.com` action; there is no Mailchimp API key, no server call, and the old D1 newsletter APIs return HTTP 410.
- **Catalog is not in D1.** It is a one-element constant (`paperback`) whose `prod_` ID comes from an env var; the price is retrieved from Stripe's Product default Price at display and at checkout time. D1 stores only snapshots on `checkout_attempts`/`order_lines`.
- **Admin access (migration 0004)**: owner = email in `ADMIN_EMAILS` secret; developer = email in `DEVELOPER_ADMIN_EMAILS` secret **and** the singleton `admin_access.developer_enabled=1` row, which only the owner can toggle from Settings. Both need verified email and a per-session TOTP proof.
- **Docs/code inconsistency worth flagging**: `docs/payments.md` describes Stripe's embedded `ui_mode: 'form'` checkout as current and the hosted endpoints as "legacy", but the shipped client script (`src/scripts/checkout.ts`) uses only the hosted-redirect flow (`/api/shipping/quote` → `/api/checkout` → `checkout.stripe.com`); nothing in `src/` references `/api/checkout/session|shipping|ready` or Stripe.js (grep in this session). The form path exists server-side and is tested.

## Q2. Commerce end to end: catalog, checkout, shipping quotes, Stripe webhook, ShipStation export, tracking return path

### Takeaway
Catalog = one constant item backed by a Stripe Product whose default Price is verified live (active, one-time, per-unit, USD, book tax code). Hosted checkout = ShipStation quick-rate quote persisted in D1 (15 min) → attempt row atomically claims the quote → per-attempt Stripe Customer + hosted Session with a fixed-amount `shipping_rate_data` from the quote → webhook reconciliation re-verifies price, address and shipping subtotal → the same D1 batch enqueues a `shipstation_exports` job → `flushShipStation` looks up by `external_shipment_id` then POSTs `/v2/shipments` with `create_sales_order: true` → ShipStation `label_created_v2`/`track_event_v2` webhooks queue jobs → cron/`waitUntil` reads canonical label + track data and updates `orders`/`order_tracking`/`fulfillment_events`. Labels are bought in ShipStation; manual shipping entry remains as a fallback.

## Q10. Security and operational observations to address before cloning this pattern

### Takeaway
