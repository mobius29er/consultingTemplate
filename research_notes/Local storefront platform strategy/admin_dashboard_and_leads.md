# Internal admin dashboard / lightweight CRM and prospect data sources (as of October 2026)

Scope note on sourcing: during this research the egress proxy blocked the primary docs hosts for Google (developers.google.com), Etsy (developers.etsy.com / etsy.com), eBay (developer.ebay.com), Yelp, Foursquare, Cloudflare (developers.cloudflare.com) and most vendor sites. Workarounds used: (a) Google Maps Platform legal terms were fetched directly from cloud.google.com; (b) Cloudflare, better-auth, Payload, Twenty and Directus docs/licenses were pulled from their open-source GitHub repos (raw.githubusercontent.com) and are therefore primary; (c) everything else relies on search-engine summaries of the vendor pages or on secondary blogs, and is marked "(secondary)" or "(unverified)". Web-search budget was exhausted before the last few gap checks; those are listed under Gaps.

## Q1. Local business discovery: Google Places API (New) — pricing, fields, caching/ToS, "no website" signal

### Takeaway
Places API (New) is the best-quality local discovery source but is priced per field tier: the fields a web consultant actually wants (websiteUri, phone, rating, userRatingCount, opening hours) are all in the Enterprise SKU of Place Details ($20 per 1,000 at 0-100K volume, 1,000 free calls/month), and Google's terms flatly prohibit storing business names/addresses/reviews — only the place_id may be stored indefinitely (lat/lng for 30 days). Practical use: search, triage, and copy a place_id into the CRM; re-fetch details on demand; never bulk-warehouse Google data.

### Cited Findings
- Pricing model change: on March 1, 2025 Google replaced the flat $200/month credit with per-SKU free monthly call thresholds: 10,000 calls for Essentials SKUs, 5,000 for Pro, 1,000 for Enterprise (secondary) — [Woosmap](https://www.woosmap.com/blog/google-places-api-pricing); [Open Places API](https://openplacesapi.com/blog/google-places-api-pricing); [StoreRocket](https://storerocket.io/learn/google-maps-api-pricing)
- Per-SKU free allowances for Places API (New): Text Search / Nearby Search Pro 5,000 free/month; Place Details Essentials 10,000 free/month; Place Details Pro 5,000 free/month; Place Details Enterprise 1,000 free/month (secondary) — [Open Places API](https://openplacesapi.com/blog/google-places-api-free-tier)
- List prices (search summary of Google's pricing page; the summary rendered Text Search Pro as "per 5,000 calls at $32.00", which is almost certainly "per 1,000" — treat the unit as unverified): Text Search Pro $32.00 (0-100K) / $25.60 (100K-500K) / $19.20 / $9.60 / $2.40 per 1,000; Place Details Enterprise $20.00 (0-100K) / $16.00 / $12.00 / $6.00 / $1.51 per 1,000 — [Google Maps Platform pricing list](https://developers.google.com/maps/billing-and-pricing/pricing)
- Place Details field-to-SKU mapping (search summary of Google's Place Details docs): Essentials IDs Only = attributions, id, name, photos; Essentials = addressComponents, formattedAddress, location, plusCode, postalAddress, shortFormattedAddress, types, viewport; Pro = businessStatus, displayName, googleMapsUri, primaryType, primaryTypeDisplayName, pureServiceAreaBusiness, timeZone, utcOffsetMinutes; Enterprise = currentOpeningHours, internationalPhoneNumber, nationalPhoneNumber, priceLevel, priceRange, rating, regularOpeningHours, userRatingCount, websiteUri; Enterprise + Atmosphere = allowsDogs, curbsidePickup, delivery, dineIn, editorialSummary, generativeSummary, goodForChildren ... (list truncated alphabetically in the excerpt; `reviews` is expected in this tier — unverified) — [Place Details (New)](https://developers.google.com/maps/documentation/javascript/place-details); [Place class data fields](https://developer.google.com/maps/documentation/javascript/place-class-data-fields)
- Field masks: billing is by the highest-tier field requested in the mask (secondary; consistent with the SKU tables above) — [Woosmap](https://www.woosmap.com/blog/google-places-api-pricing)
- Text Search (New) pagination: `maxResultCount`/`pageSize` default 20, max 20 (values above are coerced); a `nextPageToken` is returned when more results exist and official docs say up to 60 results are available via paging — [googleapis Ruby reference for GoogleMapsPlacesV1SearchTextRequest](https://googleapis.dev/ruby/google-apis-places_v1/v0.23.0/Google/Apis/PlacesV1/GoogleMapsPlacesV1SearchTextRequest.html)
- Google Maps Platform Terms §3.2.3(a) "No Scraping": "Customer will not export, extract, or otherwise scrape Google Maps Content for use outside the Services. For example, Customer will not: (i) pre-fetch, index, store, reshare, or rehost Google Maps Content outside the services; (ii) bulk download ... places information ...; (iii) copy and save business names, addresses, or user reviews" (primary, fetched directly) — [Google Maps Platform Terms of Service](https://cloud.google.com/maps-platform/terms)
- §3.2.3(b) "No Caching. Customer will not cache Google Maps Content except as expressly permitted under the Maps Service Specific Terms." §3.2.3(d)(iii): Customer will not "use the Google Maps Core Services in a listings or directory service or to create or augment an advertising product." §3.2.3(e): "Customer will not ... display or use Places content on a non-Google Map" (primary) — [Google Maps Platform Terms of Service](https://cloud.google.com/maps-platform/terms)
- Service Specific Terms §A.3 "Google ID Caching: Customer may cache the Google ID values from the Services that return such field and allow caching ... For example, Customer may cache (a) place_id from Places API" (primary) — [Google Maps Platform Service Specific Terms](https://cloud.google.com/maps-platform/terms/maps-service-terms)
- Places lat/lng caching: "Customer can temporarily cache latitude (lat) and longitude (lng) values from the Places API for up to 30 consecutive calendar days, after which Customer must delete the cached latitude and longitude values" (search summary of the archived terms) — [Maps Service Terms archive 2025-05-01](https://cloud.google.com/archive/maps-platform/terms/maps-service-terms-20250501); [Open Places API caching comparison](https://openplacesapi.com/blog/can-you-store-places-api-results)
- Attribution: Service Specific Terms §A.2 "Customer will attribute all the Services in accordance with the Documentation" (primary) — [Service Specific Terms](https://cloud.google.com/maps-platform/terms/maps-service-terms)
- Whole product category exists around "no website" leads from Google Maps (Apify actors that filter businesses with missing website/phone and score them for web-design agencies) — [Apify no-website leads actor](https://apify.com/leafy-dev-jr/no-website-business-leads-scraper-google-maps.md); [Apify webdata_labs actor](https://apify.com/webdata_labs/google-maps-no-website-leads-scraper.md)

### Inferences
- A "find local prospects" screen built on the official API costs roughly: one Text Search Pro call per query page (20 results) plus one Place Details Enterprise call per candidate you open. With 5,000 free Pro searches and 1,000 free Enterprise detail calls per month, a solo consultant triaging ~30 prospects/day stays inside the free tier; requesting websiteUri in the Text Search mask instead would bill every search at Enterprise rates, so keep the search mask to Essentials/Pro fields and fetch Enterprise fields only for shortlisted places.
- Compliance-safe storage pattern: persist only `place_id` (indefinitely allowed), your own notes, and your own derived flags (e.g., `has_website_checked_at`, `no_website=true` as your observation). Re-fetch name/phone/website live when the record is opened, or require the consultant to re-type the fields they want to keep (then it is user-entered CRM data, not cached Google content). Do not build a stored "directory" of Google-sourced businesses — §3.2.3(d)(iii) targets exactly that.
- Empty `websiteUri` is a useful first-pass signal but not reliable on its own: Google only shows a website when the owner added one to their Business Profile; businesses that use a Facebook page, Linktree, Square/Toast ordering page, or a marketplace shop often appear with no websiteUri or with a social URL. Treat it as "needs manual check" and validate with a HEAD request / manual look before pitching.
- The Enterprise + Atmosphere `reviews` field returns at most 5 reviews and the terms prohibit copying/saving reviews, so reviews cannot be used as demo-site content (see Q7).

### Gaps
- Could not load Google's pricing page directly; the exact per-1,000 prices for Text Search Essentials, Nearby Search tiers, Place Details Essentials/Pro, Autocomplete and Place Photos are not independently confirmed here (only the Text Search Pro and Place Details Enterprise tiers surfaced in search). Verify at developers.google.com/maps/billing-and-pricing/pricing.
- The Places API (New) "policies" page (display/attribution specifics, pre-fetching rules) could not be fetched; the caching rules above come from the Service Specific Terms and an archived copy.

## Q2. Local business discovery: Yelp, OpenStreetMap/Overpass, Foursquare OS Places / Overture, scrapers and data vendors, legality

### Takeaway
Yelp is now a paid-only API (from $7.99 per 1,000 calls, 300-500 calls/day caps) and does not even return the business website, so it is poor value for this use case. The free alternatives with permissive licenses are Foursquare OS Places (Apache 2.0, 100M+ POIs with `website`, `tel`, `email`, `instagram`, `facebook_id` columns) and Overture Maps places (multi-license; FSQ-sourced rows Apache 2.0, the rest CDLA-Permissive 2.0) — these can be bulk-loaded into D1 legally. Google Maps scrapers (Outscraper, Apify) are cheap but violate Google's terms; the legal risk is contractual, not criminal.

### Cited Findings
- Yelp Fusion pricing: Starter $7.99 per 1,000 calls (daily quota 300; base attributes and search filters); Plus $9.99 per 1,000 (daily quota 500; enhanced attributes, up to 3 photos, reviews endpoint); Enterprise $14.99 per 1,000 (daily quota 500; premium attributes, more photos, Review Highlights endpoint); each has a 30-day free trial (secondary) — [App Developer Magazine](https://appdevelopermagazine.com/yelp-fusion-api-outrageous-new-pricing/); [apispine](https://apispine.com/yelp); [Supergood API report card](https://supergood.ai/api-report-card/yelp)
- Yelp ended free Fusion API access in July 2024 with as little as 4 days' notice; several dependent apps shut down (secondary) — [App Developer Magazine](https://appdevelopermagazine.com/yelp-fusion-api-outrageous-new-pricing/)
- Yelp business search fields: id, alias, name, url (the Yelp page), image_url, is_claimed, is_closed, rating, review_count, price, phone/display_phone, categories, location (address, city, state, zip, country), coordinates, distance, transactions — no business-website field is in the search response — [Scrapfly on dev.to](https://dev.to/scrapfly/how-to-use-yelp-api-to-extract-business-and-review-data-3gn1); [Microsoft Yelp connector field list](https://learn.microsoft.com/connectors/yelpip)
- Yelp API terms allow 24-hour caching but not external storage of API data (secondary, older source) — [InfoQ (2016)](https://www.infoq.com/news/2016/09/yelp-fusion-api); [Elfsight](https://elfsight.com/blog/how-to-get-and-use-yelp-api)
- OSM Overpass public instance guidance: one-off use is fine under ~10,000 queries/day and <1 GB/day; for regular automated use divide by 100 (<100 queries, <10 MB/day); on HTTP 429/406 pause 30 s; commercial/production use should self-host or use a commercial provider; send an identifying User-Agent — [Overpass API User's Manual](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html); [OSM wiki: Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)
- OSM data is ODbL (attribution and share-alike for derived databases) — [OSM wiki: Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)
- Foursquare Open Source Places: 100M+ POIs across 200+ countries, 22 core attributes, Apache 2.0 license (free for commercial use), updated monthly — [Foursquare announcement](https://foursquare.com/resources/blog/products/foursquare-open-source-places-a-new-foundational-dataset-for-the-geospatial-community/); [source.coop mirror](https://source.coop/fused/fsq-os-places)
- FSQ OS Places columns: fsq_place_id, name, latitude, longitude, address, locality, region, postcode, country, tel, website, email, facebook_id, instagram, twitter, fsq_category_ids, fsq_category_labels, date_created, date_refreshed, date_closed, placemaker_url, geom, bbox; many fields are null for many places — [Foursquare Places OS schema](https://docs.foursquare.com/data-products/docs/places-os-data-schema); [ClickHouse sample dataset](https://clickhouse.com/docs/getting-started/example-datasets/foursquare-places)
- Overture places is a multi-license dataset keyed on each row's `source`: Foursquare-sourced rows are Apache 2.0, all other sources CDLA-Permissive 2.0; the Sept 2025 release added ~6M FSQ POIs; as of April 2026 Foursquare-sourced = 6,749,057 features and Meta-sourced = 59,413,511 — [Overture Places Guide](https://docs.overturemaps.org/guides/places); [Overture release notes 2025-09-24](https://docs.overturemaps.org/blog/2025/09/24/release-notes/)
- Outscraper (Google Maps scraper): 500 free records/month; pay-as-you-go $3 per 1,000 places up to 100K, $1 per 1,000 above (secondary) — [SyncGTM Outscraper review](https://syncgtm.com/blog/outscraper-review-2026); [apiserpent comparison](https://apiserpent.com/blog/google-maps-api-pricing-comparison)
- Apify Google Maps Scraper (compass/crawler-google-places): pay-per-event $0.007 per run start + $0.004 per place scraped (+$0.001 per filter); "from $1.50 / 1,000 places" on paid plans, $5 / 1,000 on the Free plan — [Apify cost of usage](https://apify.com/compass/crawler-google-places/cost-of-usage); Apify platform plan from $49/month — [Apify landing page](https://apify.com/lp/scrape-google-maps)
- Google's terms explicitly prohibit copying/saving business names, addresses, reviews and bulk download of places information (see Q1 primary quotes) — [Google Maps Platform Terms](https://cloud.google.com/maps-platform/terms); a scraping-vendor blog concedes Maps terms "prohibit bulk extraction, caching, and using Maps content to build lead lists, telemarketing lists, or substitute directories" — [Thunderbit](https://www.thunderbit.com/blog/is-scraping-google-maps-legal)
- Case law: hiQ won the CFAA/public-data question on appeal but lost on breach of contract (it had agreed to LinkedIn's User Agreement and used fake accounts), ending with a permanent injunction, data deletion and $500,000; in Meta v. Bright Data the court granted summary judgment to Bright Data because Meta's terms did not prohibit logged-out scraping of public data — [Farella Braun + Martel analysis](https://www.fbm.com/data-analytics/publications/what-recent-rulings-in-hiq-v-linkedin-and-other-cases-say-about-the-legality-of-data-scraping/); [Enrich Layer on Meta v. Bright Data](https://enrichlayer.com/blog/meta-lost-the-scraping-legal-battle-to-bright-data)
- Apollo.io Free plan: 50 AI credits/month, 5 mobile credits, 10 export credits, unlimited email credits (fair use); Basic $49/user/mo annual, Professional $79 (secondary) — [CostBench Apollo free plan](https://www.costbench.com/software/ai-sales-tools/apollo/free-plan/); [Zeliq Apollo pricing](https://www.zeliq.com/blog/apolloio-pricing)
- Data Axle Genie (Salesgenie): Basic $99/month, Pro $149/month, Team $299/month (up to 5 users) (secondary) — [G2 pricing](https://www.g2.com/products/salesgenie-by-data-axle/pricing); [Capterra](https://www.capterra.com/p/228740/Data-Axle-Genie/)
- Secretary of State bulk filings as a "new business" lead source: Ohio publishes free monthly bulk files of new filings; Indiana charges $9,500 for the full file + $500/monthly update; Kentucky and West Virginia run subscriber bulk-data services; Texas sells daily/weekly filing-update subscriptions; filed.dev sells 250,000 entity records from 5 states for $19 — [Kentucky SOS Bulk Data](https://www.sos.ky.gov/bus/Pages/Bulk-Data-Service.aspx); [Indiana INBiz bulk data](https://inbiz.in.gov/Inbiz/BulkDataServices/Index); [Texas SOS bulk](https://direct.sos.state.tx.us/help/help-corp.asp?pg=bulk); [filed.dev](https://filed.dev/dataset)

### Inferences
- Recommended free discovery stack for the dashboard: load FSQ OS Places (or Overture places filtered to your metro) into a D1 table once (Apache 2.0 allows storage and commercial use), index by category + bbox, and flag rows where `website` is null. Use Google Places (New) only as the live "verify/enrich" step keyed by place_id. This keeps Google data out of your database while still giving you a browsable, filterable local list.
- Yelp is not worth paying for here: its search response lacks the website field, the daily caps are tiny, and its 24-hour cache rule prevents storing what you fetch.
- Scraper risk is asymmetric: Google will not sue a solo consultant for a few hundred records, but it can terminate the Google Cloud/Maps account used for the client sites and the consultant's Business Profile API access. Keep scrapers (if used at all) on a throwaway account and never feed scraped Google content into client-facing sites.
- Apollo's free tier is good for enriching a named business owner's email once you already have the business; it is weak for "find every bakery within 10 miles".

### Gaps
- Yelp's current Terms of Use / Display Requirements text (lead-generation clauses) could not be fetched; the 24-hour cache rule is from a 2016 source and may have changed.
- Chamber of Commerce member directories: no sources found in this session; treat as a manual-entry source (most chambers publish a public member list on their website).
- Overture/FSQ US coverage quality for very small local businesses is uncertain; the ClickHouse sample shows many nulls in tel/website.

## Q3. Etsy Open API v3 — access levels, rate limits, public shop fields, prospecting under the ToS, messaging rules

### Takeaway
Etsy v3 exposes public shop data (name, listing_active_count, transaction_sold_count, review_average, review_count, shop_location_country_iso, url) with just an API key, but `findShops` only searches by shop name (no location/category search), apps start on provisional limits (5 req/s, 5,000/day) and Etsy's app review rejects lead-gen/AI-data uses outright; its messaging policy prohibits unsolicited advertising via Etsy Messages. Etsy is therefore a "verify a seller you already found" source, not a discovery engine.

### Cited Findings
- Access levels: the API is free for Personal access (shops you own or that grant you access); serving arbitrary sellers requires "Commercial Access", which is manually reviewed; approval typically takes around 30 days, longer when busy (secondary) — [profplum700 etsy-v3-api-client README](https://github.com/profplum700/etsy-v3-api-client); [Vorplabs Etsy API notes](https://vorplabs.com/agent-tools/etsy-api); [Rollout Etsy API essentials](https://rollout.com/integration-guides/etsy/api-essentials)
- Rate limits: default 10,000 requests per 24 hours at 10 queries/second; limits are computed as a rolling sum over two-hour blocks, so a throttled app waits at most two hours; 429 on limit; contact Etsy for more (secondary) — [node-etsy-client](https://www.npmjs.org/package/node-etsy-client); provisional/unapproved commercial apps start at 5 req/s and 5,000/day until approved (secondary) — [profplum700 client README](https://github.com/profplum700/etsy-v3-api-client)
- Etsy staff rejection of a data-heavy app in the official open-api discussions: "At this time we are not allowing these types of usage of our data. Specifically, apps that rely on AI generative content, like ChatGPT, other LLM tools, or machine learning tools." The applicant had requested 20-30K requests/day for an SEO tool targeting Etsy sellers — [etsy/open-api discussion #1387](https://github.com/etsy/open-api/discussions/1387)
- Authentication: every request carries `x-api-key`; public read-only data (shop, listings, reviews) is available with the API key alone, while seller-private endpoints need OAuth 2.0 — [publicapi.dev Etsy summary](https://publicapi.dev/etsy-api)
- `getShop` (`GET /v3/application/shops/{shop_id}`) returns, among others, `transaction_sold_count` (total sales), `review_average` (past-year average), `review_count`, `listing_active_count`, `shop_location_country_iso`, plus shop name/url/announcement (example response values 284 / 4.9 / 42 / "US") — [withone.ai Etsy getShop reference](https://www.withone.ai/knowledge/etsy/conn_mod_def%3A%3AGMUoX-ePFoI%3A%3Au5pKGesoTx2AQXVlrlvJEg)
- `findShops` (`GET /v3/application/shops`) requires `shop_name` and supports only `limit`/`offset`; it searches by name and has no location-based parameters; frozen/removed shops are excluded — [withone.ai findShops reference](https://www.withone.ai/knowledge/etsy/conn_mod_def%3A%3AGMUoX-QLFdk%3A%3ABMttpt4WSFqTL93aolAN8w); [Qodex Etsy shops reference](https://developers.qodex.ai/etsy/etsy/shops/get-shops)
- Other public listing endpoints seen in the discussion: `/v3/application/shops/{shop_id}/listings/active`, `/v3/application/listings/{listing_id}`; batching up to 100 listings per call and the `includes` parameter reduce call counts — [etsy/open-api discussion #1387](https://github.com/etsy/open-api/discussions/1387)
- A third-party app notes it caches Etsy taxonomy for "up to 24 hours to comply with Etsy API caching rules" (indirect evidence of a 24-hour cache norm; unverified against the ToS text) — [Contentsy privacy policy](https://contentsy.onrender.com/privacy)
- Etsy messaging policy (House Rules): prohibited uses of Etsy Messages include "sending unsolicited advertising or promotions, requests for donations or spam" and contacting someone after they asked you not to; Etsy disables messaging without warning when it detects unsolicited non-transactional messages — [Etsy House Rules article 4508](https://www.etsy.com/help/article/4508); [Etsy community thread](https://community.etsy.com/t5/Technical-Issues/messaging-potential-buyers/m-p/144735010/highlight/true)

### Inferences
- Realistic Etsy workflow: discover sellers manually (Etsy search by category + "ships from <your city>" filter in the browser, local craft fairs, Instagram), then paste the shop name into the dashboard, which calls `findShops`/`getShop` with your personal API key to pull listing count, sales count and rating into the `channel_listings` row. That stays inside personal-access use (you are not serving other sellers' private data) and inside provisional rate limits.
- Do not pitch through Etsy Messages; it is a policy violation that gets the sender muted. Use the external website/social links sellers put in their shop "About" section, or CAN-SPAM-compliant email to a published business address.
- Requesting Commercial Access with "lead generation for a web agency" as the use case is likely to be refused given the #1387 precedent; do not depend on it.

### Gaps
- The Etsy API Terms of Use text (etsy.com/legal/api) could not be retrieved; clauses on data retention, solicitation and competing services are unconfirmed. Reference: https://www.etsy.com/legal/api
- Whether `getShop` is reachable with a key that has only provisional/personal access was not confirmed from a primary source (secondary sources say yes for public data).

## Q4. Amazon — SP-API seller lookup, public storefront data, third-party datasets, scraping terms

### Takeaway
SP-API cannot look up third-party sellers (it only returns data for the authorizing seller's own account). Public seller profile pages on Amazon.com have shown "Detailed Seller Information" (business name and address) since September 1, 2020, but Amazon's Conditions of Use prohibit data mining/robots, so discovery has to be manual or via licensed datasets (Keepa Sellers endpoint, SmartScout's 2.26M-seller database, Jungle Scout).

### Cited Findings
- SP-API/MWS access "is limited to your own seller account data. If you need data from other sellers or more general product data, Amazon MWS may not suffice" — [WebScraping.AI FAQ](https://webscraping.ai/faq/amazon-scraping/what-are-the-limitations-of-using-amazon-mws-for-product-data-instead-of-scraping); SP-API data policy framing (seller-authorized data only) — [WeMarket SP-API privacy policy](https://wemarket.dk/amazon-sp-api-privacy-policy/)
- Amazon Conditions of Use prohibit "data mining, robots, or similar data gathering and extraction tools" and require written permission for automated or manual monitoring/copying — [Conduct Atlas summary of Amazon Conditions of Use](https://conductatlas.com/platform/amazon/amazon-conditions-of-use/user-conduct-and-prohibited-activities/); [Thunderbit on Amazon scraping](https://www.thunderbit.com/blog/is-scraping-amazon-legal)
- Since September 1, 2020 Amazon displays each US seller's business name and address on the seller profile page under "Detailed Seller Information"; for individuals it shows the individual's name and address; not optional — [TechCrunch](https://techcrunch.com/2020/07/08/amazon-u-s-sellers-will-have-to-display-their-name-and-address-starting-sept-1-2020/); [Marketplace Pulse](https://marketplacepulse.com/articles/amazon-now-lists-sellers-business-name-and-address)
- Keepa API: from €49/month for 20 tokens/minute (Starter) up to €11,099/month for 10,000 tokens/minute; no free tier; token bucket refills continuously, unused tokens expire after 60 minutes; the Sellers endpoint ("list of most rated marketplace sellers") costs 50 tokens per requested list, which contains up to 100,000 sellers — [Keepa API docs](https://keepa.com/api-docs/); [RevenueGeeks Keepa API](https://revenuegeeks.com/software/keepa/api)
- SmartScout: four tiers starting at $49/month ($29/month billed annually) up to custom Enterprise; database of 484,427 brands and 2.26 million sellers; 7-day money-back guarantee (secondary) — [AffMaven SmartScout pricing](https://affmaven.com/smartscout-pricing/); [RevenueGeeks SmartScout pricing](https://revenuegeeks.com/smartscout-pricing/)
- Jungle Scout (rebranded "Catalyst"): Starter $49/month ($29 annual), Growth Accelerator $79 ($49 annual), Brand Owner + CI $149 ($129 annual), Cobalt custom; Helium 10 retired its Starter plan in early 2026 — Platinum $129/month ($99 annual), Diamond $359 ($279 annual), plus a limited free plan (secondary) — [SellerSprite Helium 10 pricing guide](https://www.sellersprite.com/en/blog/helium-10-pricing-2026-guide); [EcomCrew comparison](https://www.ecomcrew.com/helium10-vs-junglescout/)

### Inferences
- For a local-focused consultant the cheapest compliant path is manual: search Amazon for product categories, open the seller profile, and read the "Detailed Seller Information" address to find sellers in your metro; enter them by hand. SmartScout's seller database (filterable by location/state) at $29-49/month is the only turnkey "sellers near me" option found and is worth a one-month subscription to seed the CRM.
- Keepa's Sellers endpoint returns "most rated" sellers marketplace-wide, not geographically filtered; at €49/month it is overkill unless you also want ASIN data.

### Gaps
- Whether SmartScout's seller export includes the business address/state filter was not verified from a primary page.
- Amazon's seller profile page fields beyond name/address (feedback counts, storefront link) were not captured from a primary source.

## Q5. eBay — Developers Program, Browse API seller data, Taxonomy API, rate limits, contact info, unsolicited-contact rules

### Takeaway
eBay's Developers Program is free; Browse API `item_summary/search` returns `seller.username`, `seller.feedbackScore` and `seller.feedbackPercentage` (plus `sellerAccountType` BUSINESS/INDIVIDUAL only on EU sites), with a default 5,000 calls/day per app (raise via Application Growth Check). Seller contact details are not exposed for US sellers (EU listings show business contact info by law), and eBay's spam / member-to-member policy bars using eBay-obtained info to solicit off-eBay sales.

### Cited Findings
- Browse API default call limit is 5,000 calls/day per application (application-level, not per user); higher limits after eBay's Application Growth Check — [eBay API call limits](https://developer.ebay.com/develop/get-started/api-call-limits); [eBay community thread](https://community.ebay.com/t5/eBay-APIs-Talk-to-your-fellow/About-API-limit-calls/m-p/34673055)

## Q7. Outreach legality (CAN-SPAM, TCPA, state law) and IP/ToS exposure of unsolicited demo sites

### Takeaway
Cold B2B email is legal in the US under CAN-SPAM's opt-out model (accurate headers, honest subject, ad identification, physical postal address, working opt-out honored within 10 business days; penalties up to $53,088 per email), but cold texting or autodialed/prerecorded calls to any mobile number need prior express consent under the TCPA (with revocation rules tightened April 2025/2026). Demo sites that use a business's name are defensible under nominative fair use if you use only the name (not the logo), add a clear "unsolicited concept, not affiliated" notice, and avoid copying their photos, menu text or Google/Yelp reviews — Google's terms specifically forbid copying reviews, and copyright in photos belongs to whoever took them.

### Cited Findings
- CAN-SPAM covers any commercial email including B2B cold outreach — no B2B exemption; it is opt-out, not opt-in; the core requirements are accurate "From/To/Reply-To", honest subject lines, identification as an ad, a valid physical postal address, a clear opt-out that requires no more than visiting one page, and processing opt-outs within 10 business days without selling/transferring the address; penalties up to $53,088 per email as of January 2025 (secondary summaries of the FTC guide) — [EmailListValidation](https://emaillistvalidation.com/blog/does-canspam-apply-to-b2b-cold-email-outreach/); [Prospeo CAN-SPAM guide](https://prospeo.io/s/can-spam-act-email-marketing); [LeadHaste](https://leadhaste.com/blog/can-spam-compliance-cold-email-2026)
- TCPA: B2B calls to business landlines are largely allowed, but autodialers, prerecorded messages, and any call/text to a wireless or DNC-registered number need prior express consent (written consent for marketing in some cases); penalties $500-$1,500 per call/text; the TCPA treats a business mobile number like a personal one when there is no prior relationship — [Wipfli: TCPA and B2B marketing](https://www.wipfli.com/insights/articles/does-tcpa-apply-to-b2b-marketing-key-rules); [Prospeo: cold texting](https://prospeo.io/s/cold-texting); [Prospeo: cold calling laws](https://prospeo.io/s/cold-calling-laws)
- FCC changes: since April 11, 2025 consumers can revoke consent by any reasonable means and opt-outs must be honored within 10 business days; a broader rule applying opt-outs across all message types/business units took effect April 11, 2026; the FTC expanded the Telemarketing Sales Rule's misrepresentation prohibitions to B2B calls (secondary) — [NowBAM on new cold call/text rules](https://nowbam.com/what-you-need-to-know-about-the-new-rules-for-cold-calls-texts/); [Smartlead cold-calling compliance](https://www.smartlead.ai/blog/cold-calling-compliance)
- Nominative fair use (Ninth Circuit, New Kids on the Block, applied in Playboy v. Welles): (1) the product/service must be one not readily identifiable without using the mark; (2) only so much of the mark as is reasonably necessary may be used; (3) the user must do nothing that suggests sponsorship or endorsement by the mark holder — [Playboy Enterprises v. Welles (FindLaw)](https://caselaw.findlaw.com/us-9th-circuit/1233126.html); [Davis+Gilbert on nominative fair use](https://www.dglaw.com/nominative-fair-use-defense-may-enable-use-of-anothers-trademark/)
- Google Maps Platform Terms §3.2.3(a)(iii): Customer will not "copy and save business names, addresses, or user reviews" (primary) — [Google Maps Platform Terms](https://cloud.google.com/maps-platform/terms)
- Google reviews on third-party sites: Google's terms prohibit scraping/displaying reviews other than through the Places API, which returns at most 5 reviews per place sorted by relevance — [Idukki embed guide](https://idukki.io/blog/embed-google-reviews); Google's structured-data guidelines reserve review markup for reviews "directly produced by your site", not copied from Yelp/Google Maps — [Search Engine Land](https://searchengineland.com/google-gives-thumbs-up-on-placing-your-local-reviews-from-yelp-google-maps-others-on-your-own-web-site-305009)
- Yelp provides an official per-review embed code for displaying individual Yelp reviews on a website — [BrightLocal on embedding reviews](https://www.brightlocal.com/learn/review-management/dos-and-donts/embedding-reviews/)
- Spec/pitch work using a real brand: community guidance is that unpaid concept work clearly labelled "Pitch"/"Concept" is usually tolerated and disputes are settled with disclaimer language, but publishing it widely is inadvisable (secondary, non-legal) — [Adobe Community thread](https://community.adobe.com/t5/illustrator-discussions/how-to-create-a-faux-project-remaking-an-existing-brand/m-p/13906115)

### Inferences
- Safe-harbor practice set for demo sites, each tied to a cited constraint: (1) serve demos on `demo-<slug>.yourplatform.com` with `X-Robots-Tag: noindex, nofollow` and a robots.txt disallow, so the demo cannot be mistaken for the business's real site (nominative-use factor 3); (2) gate the demo behind Cloudflare Access one-time-PIN or a per-prospect password/token link so only the recipient sees it; (3) use the business name in plain text only, never their logo or brand photography (factors 1-2); (4) use your own or licensed placeholder imagery and a generic sample menu/catalog — do not paste Google reviews, Yelp reviews, or their site's text (Google §3.2.3, copyright); (5) show a persistent banner "Unsolicited concept by <you>; not affiliated with or endorsed by <business>"; (6) delete the Worker and custom hostname immediately on request and log the takedown in the CRM; (7) hand off IP cleanly on purchase (site built on your templates, client-supplied content).
- Email outreach checklist to bake into the dashboard's email template: physical address in the footer, "Reply STOP/unsubscribe" link that flips a `do_not_contact` flag on the contact, subject line that says what it is, and a suppression check before every send. Do not add SMS as an outreach channel to numbers found on Google/Yelp.

### Gaps
- Primary FTC/FCC pages (ftc.gov, fcc.gov) were blocked; the figures above come from compliance vendors that cite them. State-level laws (e.g., Florida/Oklahoma mini-TCPAs, California CCPA implications for stored owner contact data) were not researched.
- No case law found specifically on unsolicited demo websites using a business's name; the analysis is by analogy to nominative-use doctrine.

## Q8. CRM data model, pipeline design, dedup/identity resolution, search on D1

### Takeaway
Model the CRM around an `accounts` table (the business), with many `channel_listings` (one row per Google Place / Etsy shop / Amazon storefront / eBay store / website), `contacts`, a single `deals` row per account carrying the pipeline stage, append-only `activities`, `sites` (worker name, hostname, status) and `stripe_customer_id` on the account. D1 supports FTS5 (and JSON), so use an external-content FTS5 table for search; the LIKE fallback is constrained by D1's 50-byte LIKE-pattern limit.

### Cited Findings
- D1 supports the SQLite FTS5 module for full-text search (including `fts5vocab`), the JSON extension, and math functions (primary, Cloudflare docs source) — [cloudflare-docs partial: d1-do-supported-sqlite-extensions](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/partials/d1/d1-do-supported-sqlite-extensions.mdx); [D1 SQL statements](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/d1/sql-api/sql-statements.mdx)
- D1 limits relevant to a CRM: max 100 columns per table; max 100 bound parameters per query; max 50 bytes in a `LIKE`/`GLOB` pattern; 2 MB max row/string/BLOB; 100 KB max SQL statement; 10 GB per database on Workers Paid (500 MB Free); 1,000 queries per Worker invocation on Paid (50 on Free); 30-day Time Travel on Paid (primary) — [D1 limits](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/d1/platform/limits.mdx)
- D1 LIKE search is the documented simple-search approach (`WHERE CompanyName LIKE ?` bound with `%eve%`) (primary) — [D1 SQL statements](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/d1/sql-api/sql-statements.mdx)
- D1 export does not support virtual tables (databases containing FTS5 virtual tables cannot be exported with `wrangler d1 export`) (secondary; from a Cloudflare-docs-derived search summary) — [zenn.dev D1 FTS write-up](https://zenn.dev/cybozu_frontend/articles/cloudflare-d1-fts)
- Only `place_id` may be stored indefinitely from Google; lat/lng for 30 days; nothing else (see Q1) — [Service Specific Terms](https://cloud.google.com/maps-platform/terms/maps-service-terms)
- Stripe customer linkage and per-client credentials are addressed in Q10 (Workers secrets limits: 64 variables per Worker on Free, 128 on Paid, 5 KB each) — [Workers limits](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/workers/platform/limits.mdx)

### Inferences
Proposed schema (SQLite/D1, all ids TEXT ulid/uuid, timestamps as ISO-8601 TEXT or INTEGER epoch):

```sql
-- the business ("account")
CREATE TABLE accounts (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, name_norm TEXT NOT NULL,      -- lowercased, punctuation/stopwords stripped
  kind TEXT CHECK(kind IN ('local','etsy','amazon','ebay','webstore','mixed')) NOT NULL DEFAULT 'local',
  street TEXT, city TEXT, region TEXT, postal TEXT, country TEXT DEFAULT 'US',
  phone_e164 TEXT, email_domain TEXT, website_url TEXT, website_tech TEXT,   -- 'shopify','wix','squarespace','woocommerce','none','custom'
  lat REAL, lng REAL, geo_cached_at TEXT,                                 -- lat/lng must be purged within 30 days if Google-sourced

  created_at TEXT, updated_at TEXT, archived_at TEXT
);
CREATE INDEX accounts_name_norm ON accounts(name_norm);
CREATE INDEX accounts_phone ON accounts(phone_e164);
CREATE INDEX accounts_domain ON accounts(email_domain);
CREATE UNIQUE INDEX accounts_stripe ON accounts(stripe_customer_id) WHERE stripe_customer_id IS NOT NULL;

-- one row per external presence; the dedup backbone
CREATE TABLE channel_listings (
  id TEXT PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(id),
  channel TEXT NOT NULL CHECK(channel IN ('google_place','fsq','overture','yelp','etsy','amazon','ebay','website','instagram','facebook','other')),

  metrics_json TEXT,                    -- {"rating":4.9,"review_count":42,"listing_active_count":42,"transaction_sold_count":284,"feedbackScore":1203}

CREATE TABLE contacts (
  id TEXT PRIMARY KEY, account_id TEXT REFERENCES accounts(id),
  first_name TEXT, last_name TEXT, role TEXT, email TEXT, email_norm TEXT, phone_e164 TEXT,
  consent_email INTEGER DEFAULT 0, consent_sms INTEGER DEFAULT 0, unsubscribed_at TEXT,
  source TEXT, created_at TEXT, updated_at TEXT
);
CREATE UNIQUE INDEX contacts_email ON contacts(email_norm) WHERE email_norm IS NOT NULL;

-- pipeline: one open deal per account
CREATE TABLE deals (
  id TEXT PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(id),
  stage TEXT NOT NULL CHECK(stage IN ('lead','demo_built','demo_sent','call','paid','live','managed','handed_off','lost')),
  stage_entered_at TEXT, next_action TEXT, next_action_at TEXT,
  plan TEXT, mrr_cents INTEGER, setup_fee_cents INTEGER, lost_reason TEXT,

CREATE INDEX deals_stage ON deals(stage, next_action_at);

CREATE TABLE deal_stage_history (id TEXT PRIMARY KEY, deal_id TEXT, from_stage TEXT, to_stage TEXT, at TEXT, note TEXT);

-- notes, calls, emails, tasks: append-only
CREATE TABLE activities (
  id TEXT PRIMARY KEY, account_id TEXT NOT NULL, contact_id TEXT, deal_id TEXT,
  type TEXT CHECK(type IN ('note','email_out','email_in','call','sms','task','demo_view','system')),

CREATE INDEX activities_due ON activities(done_at, due_at) WHERE type='task';

-- the site(s) you build for them; mirrors Cloudflare state
CREATE TABLE sites (
  id TEXT PRIMARY KEY, account_id TEXT NOT NULL REFERENCES accounts(id),
  kind TEXT CHECK(kind IN ('demo','production')), template TEXT, template_version TEXT,
  dispatch_namespace TEXT, script_name TEXT UNIQUE,            -- WfP user Worker name, e.g. 'site-<accountslug>'
  preview_hostname TEXT,                                       -- '<slug>.demo.yourplatform.com'
  custom_hostname TEXT, custom_hostname_id TEXT,               -- Cloudflare for SaaS custom hostname id
  hostname_status TEXT, ssl_status TEXT, hostname_checked_at TEXT,
  d1_database_id TEXT, r2_bucket TEXT, kv_namespace_id TEXT,
  status TEXT CHECK(status IN ('draft','building','preview','live','suspended','deleted')),

  last_deploy_job_id TEXT, created_at TEXT, updated_at TEXT

CREATE TABLE deploy_jobs (
  id TEXT PRIMARY KEY, site_id TEXT NOT NULL, action TEXT CHECK(action IN ('build_demo','deploy','go_live','attach_domain','suspend','delete')),

  workflow_instance_id TEXT, requested_by TEXT, created_at TEXT, started_at TEXT, finished_at TEXT

CREATE TABLE subscriptions (
  id TEXT PRIMARY KEY, account_id TEXT NOT NULL, stripe_subscription_id TEXT UNIQUE, stripe_price_id TEXT,

CREATE TABLE tags (id TEXT PRIMARY KEY, name TEXT UNIQUE, color TEXT);
CREATE TABLE account_tags (account_id TEXT, tag_id TEXT, PRIMARY KEY(account_id, tag_id));

-- search: external-content FTS5 over accounts + contacts, maintained by triggers
CREATE VIRTUAL TABLE search_idx USING fts5(entity, entity_id UNINDEXED, name, city, phone, email, notes, tokenize='unicode61 remove_diacritics 2');
```

- Identity resolution across sources (same bakery = Google place + FSQ row + Instagram): resolve in this order and record the winning rule on the `channel_listings` row — (1) exact `UNIQUE(channel, external_id)` hit; (2) E.164 phone match (normalize `+1` and strip formatting); (3) website host match (strip `www.`, lowercased; also compare `email_domain`); (4) `name_norm` + postal code match, where `name_norm` lowercases, strips punctuation and tokens like "llc", "inc", "the", "co"; (5) fuzzy: `name_norm` FTS5 prefix match within ~500 m (haversine in SQL on lat/lng) surfaced as a "possible duplicate" card for the human to confirm. Never auto-merge on rule 5; a merge moves all `channel_listings`, `contacts`, `activities`, `deals` to the survivor and writes a `merged_into` tombstone.
- Search approach on D1: FTS5 is available, so use one external-content FTS5 table (`search_idx`) fed by INSERT/UPDATE/DELETE triggers, query with `MATCH 'bak*'` for prefix typing, and rank with `bm25()`; the search box should hit FTS5 first and fall back to `LIKE` on `name_norm`/`phone_e164` for short numeric strings. The LIKE fallback must keep patterns under D1's 50-byte limit (truncate the user's input). Because D1 export does not support virtual tables, keep `search_idx` rebuildable from source tables (external-content FTS5 stores no copy of the text) and drop/recreate it around exports; use the trigram tokenizer only if substring (not prefix) search is essential (trigram availability on D1's SQLite build is unverified).
- Google-sourced hygiene: a nightly cron Worker nulls `lat`,`lng` where `geo_cached_at` is older than 30 days and `source='google'`; FSQ/Overture-sourced coordinates (Apache 2.0 / CDLA) can stay.
- Pipeline rules worth enforcing in code: `demo_built` requires a `sites` row with status `preview`; `demo_sent` requires an `activities` row of type `email_out`/`sms` with consent checks; `paid` requires `stripe_customer_id` + an active `subscriptions` row (set by the Stripe webhook, not by hand); `live` requires `sites.hostname_status='active' AND ssl_status='active'`; `handed_off` records who owns the Cloudflare zone afterwards.

### Gaps
- Whether D1's SQLite build includes the FTS5 `trigram` tokenizer was not verified (sqlite.org and Cloudflare docs host blocked; the supported-functions list is in cloudflare/workerd `src/workerd/util/sqlite.c++`).
- The D1 export/virtual-table limitation was confirmed only via a secondary write-up of the Cloudflare docs.

### Inferences

Reuse the existing `/admin` layout and inbox.

## Q10. Dashboard ↔ Cloudflare link — deploy pattern, Workers for Platforms API, custom hostnames, SSL polling, token scopes, per-client secrets

### Takeaway
Use Workers for Platforms ($25/month, 20M requests, unlimited scripts): the dashboard inserts a `deploy_jobs` row and starts a Cloudflare Workflow instance that (1) builds or selects the Astro site bundle, (2) `PUT`s it to `/accounts/{account_id}/workers/dispatch/namespaces/{ns}/scripts/{script_name}` with bindings, per-site `secret_text` values and tags, (3) creates a Cloudflare for SaaS custom hostname (100 included free, $0.10/extra) and (4) polls the custom-hostname GET until `result.status` and `result.ssl.status` are both `active`, writing each step back to D1. Per-client Stripe/ShipStation/Mailchimp keys belong in the user Worker's own secret bindings (64/128 per Worker), with Secrets Store (beta; 100 secrets/account) as the option for shared platform keys.

### Cited Findings
- Workers for Platforms pricing: $25/month; 20M requests included (+$0.30/M), 60M CPU-ms included (+$0.02/M), 1,000 scripts included (+$0.02 per additional script); one request billed across dispatch → user → outbound Worker chain; max 30 s CPU per invocation (primary) — [WfP pricing](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/cloudflare-for-platforms/workers-for-platforms/reference/pricing.mdx); "Cloudflare provides an unlimited number of scripts for Workers for Platforms customers"; max 8 tags per script; `caches.default` disabled in namespaced scripts; gradual deployments not supported for user Workers (primary) — [WfP limits](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/cloudflare-for-platforms/workers-for-platforms/reference/limits.mdx)
- Upload user Worker: `PUT https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/workers/dispatch/namespaces/$NAMESPACE_NAME/scripts/$SCRIPT_NAME` as multipart with `metadata` JSON (`main_module`, `bindings`, `tags`, `compatibility_date`) and the module file typed `application/javascript+module`; TypeScript SDK `client.workersForPlatforms.dispatch.namespaces.scripts.update(namespace, scriptName, { account_id, metadata, files })`; static assets via `POST .../scripts/$SCRIPT_NAME/assets-upload-session` then `POST /accounts/$ACCOUNT_ID/workers/assets/upload?base64=true` then the PUT; list scripts `GET .../scripts`; bulk delete by tag `DELETE .../scripts?tags=customer-123:yes`; delete one `DELETE .../scripts/$SCRIPT_NAME` (primary) — [WfP platform examples](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/cloudflare-for-platforms/workers-for-platforms/reference/platform-examples.mdx)

- Cloudflare for SaaS plan limits: 100 hostnames included on Free/Pro/Business, max 50,000, $0.10 per additional hostname/month; custom origin yes; wildcard custom hostnames and custom certificates Enterprise-only (primary) — [Cloudflare for SaaS plans](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/cloudflare-for-platforms/cloudflare-for-saas/plans.mdx)

### Inferences
- Job pattern ("Build demo" / "Deploy" / "Go live"): the Astro admin action handler validates the request (admin role), inserts `deploy_jobs(status='queued')`, and calls `env.DEPLOY_WORKFLOW.create({ id: jobId, params })`. The Workflow's steps: `step.do('bundle')` — fetch the prebuilt template bundle for `template@version` from R2 (build Astro once per template version in CI, not per client; the per-client differences are bindings/vars/content in the site's own D1); `step.do('upload')` — PUT to the dispatch namespace with `metadata.bindings` = [D1, R2, KV, `{"type":"plain_text","name":"SITE_ID",...}`, `{"type":"secret_text","name":"STRIPE_SECRET_KEY","text":...}`] and `tags: ["account-<id>", "demo"|"prod"]`; `step.do('route')` — write `hostname:<slug>.demo.yourplatform.com → script_name` to the routing KV; for go-live, `step.do('custom_hostname')` POST then `step.sleep`/retry loop polling GET until both statuses are `active` (the Workflow can sleep for days while the client fixes DNS); each step writes its result into `deploy_jobs.result_json` and `sites`. Workflows beat Queues here because the job is multi-step, long-lived and needs retries/state; Queues remain useful for fan-out notifications. (The `secret_text`/`plain_text` binding type names are from Cloudflare's multipart-upload metadata reference, which was not fetched — verify.)
- Token design: create one account-owned API token used only by the Workflow Worker (stored as a Worker secret on the admin Worker): Account → Workers Scripts: Edit, Workers KV Storage: Edit, D1: Edit, R2: Edit (as needed), plus Zone (SaaS zone only) → SSL and Certificates: Edit and DNS: Edit if you also create the preview CNAMEs programmatically. Do not use a Global API Key. Whether a separate "Workers for Platforms" permission group is required for dispatch-namespace uploads was not confirmed — test with Workers Scripts: Edit first.
- Per-client credentials: Workers secrets attached to the user Worker (`secret_text` bindings in the upload metadata) are the simplest and are isolated per site by WfP's binding model; the 64/128-variable cap is far above what a storefront needs. Keep only non-secret references (Stripe customer/account id, "has_shipstation_key=true", last-rotated date) in D1; if you must store a secret in D1 (e.g., to re-upload on redeploy), encrypt it with AES-GCM under a key held as an admin-Worker secret and never render it in the UI. Secrets Store fits shared platform-level keys (your Resend/Mailchimp master keys) more than per-client keys given the 100-secret account limit and its beta status.
- Status surface in the dashboard: per site show `script_name`, preview URL, `custom_hostname` with `hostname_status`/`ssl_status` chips and a "Re-check" button (PATCH refresh), the last 5 `deploy_jobs`, and a "Delete everything for this account" that issues `DELETE .../scripts?tags=account-<id>:yes` plus hostname deletion.

## Q11. UI/table libraries for a data-dense Astro-on-Workers admin, and auth hardening for a single-admin app

### Takeaway
Keep tables server-rendered by Astro with URL-state pagination/sorting (cheap on Workers, no hydration), and hydrate a single React island with TanStack Table (`manualPagination`/`manualSorting`) only for the pipeline board and bulk-edit grids. Harden auth in layers: better-auth `@better-auth/passkey` for phishing-resistant login, better-auth admin roles for authorization, and Cloudflare Access (free for ≤50 users) in front of `/admin` with a one-time-PIN or IdP policy plus an IP-range/country Require rule.

### Cited Findings
- TanStack Table supports server-side pagination/sorting via `manualPagination: true` and `manualSorting: true`, with table state changes driving data fetches — [TanStack Table pagination guide](https://tanstack.com/table/latest/docs/framework/react/guide/pagination); [with-tanstack-query example](https://tanstack.com/table/latest/docs/framework/react/examples/with-tanstack-query)
- better-auth passkey plugin: `npm install @better-auth/passkey`, server `passkey()` plugin and client `passkeyClient()`; powered by SimpleWebAuthn; supports passkey-first registration without a session (`registration.requireSession: false` with `resolveUser`), `authenticatorAttachment` platform/cross-platform, WebAuthn extensions (PRF, credProps, largeBlob); run `npx auth migrate` to add its tables (primary) — [better-auth passkey docs](https://github.com/better-auth/better-auth/blob/main/docs/content/docs/plugins/passkey.mdx)
- better-auth admin plugin: `adminUserIds` or `admin` role gate admin APIs; `create-admin` CLI; custom roles/permissions via access controller (primary) — [better-auth admin docs](https://github.com/better-auth/better-auth/blob/main/docs/content/docs/plugins/admin.mdx)
- Cloudflare Access is free for up to 50 users; paid seats from $7/user/month (secondary) — [Cloudflare Access product page](https://www.cloudflare.com/teams-access/); [Cloudflare blog: Teams plans](https://blog.cloudflare.com/teams-plans)
- One-time PIN: add an identity provider of `type: "onetimepin"` (dashboard, `POST /accounts/{account_id}/access/identity_providers`, or Terraform); new Zero Trust orgs default to the Cloudflare identity provider and OTP is no longer added automatically; the emailed PIN expires after 10 minutes; grant access by adding the email to an Access policy (primary) — [Access one-time PIN docs](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/cloudflare-one/integrations/identity-providers/one-time-pin.mdx)
- Access policy selectors include `IP ranges` (IPv4/IPv6 CIDR), `Country`, `Emails ending in`, and Service Tokens (for machine access with the Service Auth action); `Require` rules act as AND, `Include` as OR, `Exclude` removes (primary) — [Access policies](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/cloudflare-one/access-controls/policies/index.mdx)
- Cloudflare's own "internal sites" WfP template protects every published site with Cloudflare Access (primary) — [WfP get started](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/cloudflare-for-platforms/workers-for-platforms/get-started.mdx)

### Inferences
- Table strategy for D1: paginate with keyset cursors (`WHERE (updated_at, id) < (?, ?) ORDER BY updated_at DESC, id DESC LIMIT 50`) rather than OFFSET; D1's 100-bound-parameter and 50-byte LIKE limits make "one query per view" with a small filter vocabulary the safe design. Render `<table>` server-side in `.astro` with sort/filter in the query string; add `client:load` React only for the kanban (drag between stages) and inline-edit grids. Plain Tabulator or HTMX are viable alternatives, but TanStack keeps you inside the React island the client sites already use.
- Auth layering for one admin, one future helper: (1) Cloudflare Access app on `admin.yourplatform.com` with Include = your two emails (OTP or Google IdP) and Require = IP ranges of home/office or Country = US — this blocks the login page itself from the internet; (2) better-auth session with passkey as the primary factor and the admin plugin role check in Astro middleware for every `/admin/*` route and action; (3) Access service token for the Workflow/cron callers; (4) rotate the Cloudflare API token and keep it only as a Worker secret. For demo sites, reuse the same Access setup with a per-demo policy (prospect's email via OTP) or a signed link token checked in the user Worker.
