# Payments, commerce, POS and accounting integrations for the owner "app menu"

Scope: US market, October 2026. Serves the founder vision in `founder_vision.md`: one reusable engine (Astro on Cloudflare Workers, D1, better-auth, Stripe Checkout, ShipStation, Mailchimp already in production), an owner dashboard with an app-store-like menu of integrations that uses OAuth wherever possible and API keys/webhooks as the fallback, secondary customers migrating off Shopify/Wix/Squarespace/BigCommerce/WooCommerce, and a solo founder who must get approved for integrations within weeks.

Sandbox note: the egress proxy blocked every vendor developer portal (stripe.com incl. edge-docs/support, developer.paypal.com and paypalobjects.com, developer.squareup.com, shopify.dev, docs.clover.com, doc.toasttab.com, developers.lightspeedhq.com and x-series-api, developer.intuit.com, developer.xero.com, developer.waveapps.com, devdocs.helcim.com, developer.zettle.com, developer.authorize.net, developer.woocommerce.com, nango.dev, merge.dev, developers.apideck.com and most aggregator/pricing sites). Items marked "(via search summary)" were seen only as search-engine extracts of the cited page; items marked "(unverified)" are from my training knowledge with the last figure and date I know, and must be checked before being quoted to a customer.

## Key question 1: Which integrations are realistic for a solo founder to get approved for within weeks, and what do their APIs expose for a storefront?

### Takeaway
Self-serve, no-human-review OAuth exists today for Stripe (Connect Standard via Account Links), Square (unlisted production OAuth app), Shopify (Partner app for import), BigCommerce (single-store/unlisted app), Lightspeed Retail X-Series (up to 30 stores unapproved), QuickBooks Online (questionnaire, no marketplace listing needed), Xero (uncertified app, 25-connection cap), Wave (Pro/Advisor businesses only), Mailchimp and Clover (after a production developer-account review). Human-gated with a sales/partner contact are PayPal Commerce Platform (partner vetting), Toast (partner agreement or per-restaurant standard credentials), Lightspeed Restaurant K-Series (partner program), Square App Marketplace listing (currently paused for unassigned developers), and Helcim's revenue-share partner program. API-key-only (no OAuth at all, or OAuth not worth it) are WooCommerce, ShipStation, Helcim, Authorize.net merchant keys and Toast standard access.

### Cited Findings

Stripe (payments, tax, application fees)
- Stripe says OAuth "is not recommended for new Connect platforms" and recommends Connect Onboarding (Account Links) for Standard accounts: "You use the /v1/accounts API to create a new account and get the account ID", prefill, then generate an account link — [Stripe: Standard accounts](https://docs.stripe.com/connect/standard-accounts) (via search summary); OAuth "can still be used if you're an extension or an application that needs access to an existing account" — [Stripe: OAuth for Standard accounts](https://docs.stripe.com/connect/oauth-standard-accounts.md) (via search summary).
- Stripe isolated platform activity: "platforms using OAuth with read_write scope can't connect to Standard accounts that are controlled by another platform"; such a user is directed "to create a separate Standard account to use with your platform" — [Stripe: OAuth changes for Standard platforms](https://docs.stripe.com/connect/oauth-changes-for-standard-platforms) (via search summary).
- Nango's Stripe Connect registration guide rates Stripe: paid dev account not required (free self-signup), free test mode "with full access to API and Connect features", partnership not required, "App review: Required to go live with Standard Connect (OAuth-based) applications", security audit not required — [Nango docs: register your own Stripe OAuth app](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/api-integrations/stripe/how-to-register-your-own-stripe-api-oauth-app.mdx).
- Nango's Stripe App page: "You must have an activated Stripe account (submit business info). No charges required, but activation is mandatory"; partnership "Not required to develop or publish apps"; app review "Required if you want to publish the app publicly on the Stripe App Marketplace"; a Stripe App manifest can set `stripe_api_access_type: oauth` and `distribution_type: public` with an allowed redirect URI — [Nango docs: Stripe App](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/stripe-app.mdx).
- Stripe App Marketplace review requirements include "transparent pricing ... apps should clearly state pricing without hidden costs" — [Stripe: Stripe Apps review requirements](https://docs.stripe.com/stripe-apps/review-requirements) (via search summary).
- Application fees: "The value of application_fee_amount must be positive and less than the amount of the charge. There are no additional Stripe fees on the application fee itself"; for Standard-account marketplaces "you're responsible for paying Stripe fees, which include transaction fees, per-connected account fees, and dispute fees" — [Stripe: Connect app fees](https://docs.stripe.com/connect/saas/tasks/app-fees) (via search summary).
- Stripe Tax: two plans, "Tax Complete (registrations, calculations, collections, and filings, priced as a monthly subscription with a 1-year contract) and Tax Basic (calculations and collections only, pay-as-you-go)"; PAYG no-code "0.5% of the volume processed, in jurisdictions where you are registered to collect tax"; API "Transaction API price per call is 0.50 USD and the Calculation API price per call is 0.05 USD" — [Stripe Support: Understanding Stripe Tax pricing](https://support.stripe.com/questions/understanding-stripe-tax-pricing) (via search summary).
- Nango's providers list carries four Stripe auth variants: `stripe` (Connect OAuth at connect.stripe.com/oauth/authorize), `stripe-app` (marketplace.stripe.com/oauth/v2/authorize, PKCE disabled), `stripe-express`, and `stripe-api-key` (BASIC) — [NangoHQ/nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml).
- (unverified, last known) US standard online card pricing 2.9% + $0.30 per successful card charge; Connect Standard accounts carry no per-account monthly fee while Express/Custom do; Standard accounts are supported by Checkout Sessions with `stripe_account` header for direct charges. Known as of 2025; not re-confirmed because stripe.com is blocked.

### Inferences
- "Within weeks" is realistic for: Stripe Connect Standard (self-serve; the "review" is Stripe's Connect platform profile/activation, not a marketplace review), Square unlisted OAuth app (self-serve production credentials; only the Marketplace listing is gated and paused), Shopify Partner app for import (self-serve dev app; public-distribution review is only needed if the founder wants strangers installing it — for migration he can instead ask the owner to create a custom app and paste the token), QuickBooks (30-40 minute questionnaire), Xero (instant, 25-connection cap that becomes a real ceiling only after ~25 customers), Mailchimp, ShipStation, WooCommerce, BigCommerce single-store app, Lightspeed X-Series (30 stores unapproved), Clover (developer-account approval, timeline unknown).
- Human-gated and should be deferred: PayPal Commerce Platform partner status (sales-manager-driven), Toast partner program, Lightspeed K-Series, Helcim partner program, Square Marketplace listing. For PayPal the practical answer is "PayPal Checkout with the merchant's own REST app credentials" (API-key style) until volume justifies partner onboarding.
- For a storefront engine the data surface needed is covered by Square (Catalog, Inventory, Orders, Customers, Payments/Refunds, webhooks), Clover (inventory, orders, payments), Lightspeed X-Series (products, inventory, sales), Shopify/WooCommerce/BigCommerce (products, variants, images, inventory, orders, customers for import), and Stripe (payments, refunds, customers, tax). Toast exposes menus and orders but behind gating.
- Stripe's isolation rule matters for the founder's model: a restaurant that already runs on a Stripe-controlled platform (e.g., a Toast or Squarespace-managed Stripe account) will be forced into a new Standard account when connecting to this platform. Expect this at onboarding and explain it.

## Key question 4: What does the connection flow look like in the owner's dashboard for each integration?
