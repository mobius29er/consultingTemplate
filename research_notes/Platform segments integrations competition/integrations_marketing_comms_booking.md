# Marketing, communications, booking, reviews and social integrations for the app menu

Researcher note, 5 October 2026, US market. Serves the founder vision (one engine on Cloudflare Workers; dashboard with an app-store menu of integrations; OAuth wherever possible, API keys and webhooks as fallback; primary customers have no website, secondary customers are switching platforms).

Sourcing caveat: the sandbox egress proxy blocked nearly every vendor developer portal (Mailchimp, Klaviyo, Constant Contact, Meta, TikTok, Calendly, Cal.com, Square, OpenTable, Resy, Zapier, Make, Twilio, Yelp, developers.google.com). Facts below come from (a) Google API discovery documents fetched live, (b) the open-source Nango provider catalog and Cloudflare docs on raw.githubusercontent.com fetched live, and (c) WebSearch result summaries of vendor pages. Items from (c) that could not be opened are marked "(search summary)"; anything weaker is marked "(unverified)".

Auth-mode facts cited to "Nango providers.yaml" come from https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml (fetched 2026-10-05); Nango is an open-source OAuth broker whose catalog records each vendor's real auth mode and endpoints.

## Key question 1: What should the app menu offer, and for each integration: OAuth, gating, webhooks, cost, and what the site does with it

### Takeaway
Most marketing and booking vendors that matter to a small business offer self-serve OAuth2 (Mailchimp, Constant Contact, Klaviyo, Calendly, Acuity, Square, Cal.com), the transactional/SMS layer is API-key only (Resend, Postmark, Twilio, Brevo, ActiveCampaign), and the hard gates are all platform-side: Google Business Profile (manual application), Meta Instagram/Facebook/Messenger (App Review plus Business Verification), TikTok (manual review), OpenTable/Resy (partner agreements), Booksy (no API), Vagaro (paid-tier request form).

#### Email marketing

- Mailchimp authenticates with OAuth2 at login.mailchimp.com/oauth2/authorize and /token; Nango runs a post-connection script to fetch the data center prefix — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)
- "Mailchimp do not use scopes during Authorization" and the integration needs the account's `dc` (data center) value — [Nango Mailchimp notes](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/mailchimp.mdx)
- Registering a Mailchimp OAuth app is self-serve: Account > Extras > API Keys > "Register and Manage Your Apps", fill in name/description/website/redirect URI, Client ID and (one-time) Client Secret are issued immediately; no approval step is described — [CData guide (search summary)](https://cdn.cdata.com/help/CMJ/ado/pg_oauthcustomappcreate.htm); [StackOne Mailchimp OAuth (search summary)](https://docs.stackone.com/connectors/mailchimp/guides/connector-profile/oauth-2-0); official reference [Mailchimp OAuth2 guide (blocked, not opened)](https://mailchimp.com/developer/marketing/guides/access-user-data-oauth-2/)
- Mailchimp's 2026 Free plan: 250 contacts and 500 sends per month, announced mid-January 2026, effective 17 February 2026 — [Beehiiv blog (search summary)](https://beehiivblog.beehiiv.com/p/navigating-mailchimp-s-new-free-limits-essential-updates-for-newsletter-owners); also a 250 sends/day cap and no automated journeys on Free after the Classic Automation Builder was removed in June 2025 — [Costbench (search summary)](https://costbench.com/software/marketing-automation/mailchimp/free-plan)
- Conflict: Costbench states API access is "typically limited or not available" on Free — [Costbench (search summary)](https://www.costbench.com/software/email-marketing/mailchimp-email/free-plan/) — while Sage reports the free-plan changes as affecting its CRM integration customers, implying the API still works on Free — [Sage CRM community post (search summary)](https://communityhub.sage.com/sage-global-solutions/sage-crm/b/talking-about-customers/posts/impact-of-mailchimp-free-plan-changes-on-sage-crm-customers). The founder's own CatholicJoe stack already uses Mailchimp, so this can be checked on a free test account (unverified either way).
- Klaviyo offers both an API-key provider and an OAuth2 provider (www.klaviyo.com/oauth/authorize, a.klaviyo.com/oauth/token) — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml); private keys are created under Settings > API keys with Custom/Read-Only/Full Access scopes and shown once — [Nango Klaviyo connect guide](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/klaviyo/connect.mdx); OAuth apps have a different rate-limit regime than API keys — [Nango Klaviyo OAuth notes](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/klaviyo-oauth.mdx)
- Klaviyo requires OAuth for all published partners and will delist non-OAuth apps; only OAuth apps are considered for the App Marketplace — [Klaviyo: Migrate to OAuth (search summary)](https://developers.klaviyo.com/en/docs/migrate_to_oauth_from_private_key_authentication)
- Until an OAuth app is reviewed, users see an installation warning that the app "has not been reviewed by Klaviyo" but can still install and use it; marketplace submission is optional and opens once the app has 5+ installs with API activity; Klaviyo may decline any listing — [Klaviyo: Submit your app for review (search summary)](https://developers.klaviyo.com/en/docs/submit_your_app_for_review)
- Constant Contact V3 API requires OAuth2 (authorization code flow, rotating refresh tokens, `offline_access` scope for refresh tokens, scopes such as `contact_data`); apps are created self-serve in the V3 developer portal "My Applications" tab — [Constant Contact auth overview (search summary)](https://developer.constantcontact.com/api_guide/auth_overview.html); [apps_create (search summary)](https://developer.constantcontact.com/api_guide/apps_create.html); endpoints are authz.constantcontact.com/oauth2/default/v1 — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)
- Brevo: API key only (auth_mode API_KEY; keys generated in the account's "API keys & MCP" tab with a name and expiry) — [Nango Brevo notes](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/brevo-api-key.mdx); [MoneyForward Brevo setup (search summary)](https://support.i.moneyforward.com/en/integrations/brevo)
- ActiveCampaign: API key plus account hostname, sent as `Api-Token` header; default rate limit 5 requests/second per account; no OAuth — [Nango ActiveCampaign notes](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/active-campaign.mdx); [Nango connect guide](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/active-campaign/connect.mdx)

#### Google Business Profile and Google reviews

- Access to the Business Profile APIs requires a Google API Console project, an Organization account, and a request via the GBP API contact form ("Application for Basic API Access"), submitted from an email that is an owner/manager on the business's profile; the profile must be verified, active for at least 60 days, and have a website listed — [Google prerequisites page (search summary)](https://developers.google.com/my-business/content/prereqs); [Unified.to setup guide (search summary)](https://unified.to/blog/how_to_set_up_google_business_profile_api_access_and_get_oauth_2_credentials)
- Review time: "reviewed within 14 days" per Google's FAQ; third parties report 3-10 business days; approval is a manual gate separate from enabling the API — [Google FAQ (search summary)](https://developers.google.com/my-business/content/faq); [2026 GBP API guide (search summary)](https://singhamandeep.com/?p=1592)
- Business Information API v1 Location resource includes `websiteUri`, `regularHours`, `specialHours`, `moreHours`, `phoneNumbers`, `categories`, `storefrontAddress`, `openInfo`, `profile`; `locations.patch` "Updates the specified location"; `websiteUri` is described as "Optional. A URL for this business. If possible, use a URL that represents this individual business location" — [Business Information API discovery document (fetched live)](https://mybusinessbusinessinformation.googleapis.com/$discovery/rest?version=v1)
- `locations.patch` takes an `updateMask` FieldMask; the field was renamed from `websiteUrl` to `websiteUri` — [locations.patch reference (search summary)](https://developers.google.com/my-business/reference/businessinformation/rest/v1/locations/patch); [Business Information change log (search summary)](https://developers.google.com/my-business/content/businessinformation/change-log?hl=es-419)
- Account Management API lets an app list the authenticated user's accounts and locations, invite admins, and transfer locations between accounts — [Account Management API discovery document (fetched live)](https://mybusinessaccountmanagement.googleapis.com/$discovery/rest?version=v1)
- Notifications API supports Pub/Sub notification types including NEW_REVIEW, UPDATED_REVIEW, NEW_QUESTION, NEW_CUSTOMER_MEDIA, GOOGLE_UPDATE and LOSS_OF_VOICE_OF_MERCHANT — [Notifications API discovery document (fetched live)](https://mybusinessnotifications.googleapis.com/$discovery/rest?version=v1)
- The API can create local posts (updates, events, offers), reply to reviews and read `ReviewReplyState`, access review media, update regular and special hours, manage photos, check verification status, and read performance metrics — [Google latest updates (search summary)](https://developers.google.com/my-business/content/latest-updates); [Bundle.social GBP Posts API (search summary)](https://bundle.social/google-business-profile-posts-api)
- Places API (New) Place resource: `reviews` is "a list of reviews about this place, sorted by relevance. A maximum of 5 reviews can be returned"; `rating` is 1.0-5.0; `userRatingCount` is the total review count; each Review carries `authorAttribution`, `rating`, `text`, `publishTime`, `googleMapsUri` and `flagContentUri` — [Places API (New) discovery document (fetched live)](https://places.googleapis.com/$discovery/rest?version=v1)
- Places policy: attributions for place details, photos and reviews must be retrieved and displayed; reviews must show the author's name in close proximity, with the author photo and profile link recommended; when displayed without a Google map, the Google logo must appear; the app must publish Terms of Use and a Privacy Policy that incorporate Google's — [Places API policies (search summary)](https://developers.google.com/maps/documentation/places/web-service/policies)

#### Yelp

- Yelp Fusion moved to paid plans: after a 30-day trial the minimum is $229/month; the Plus plan ($9.99 per 1,000 calls) includes the reviews endpoint, Enterprise ($14.99 per 1,000) adds Review Highlights; the reviews endpoint returns at most 3 excerpts on Base/Plus and 7 on Enterprise/Premium, never full review text; last verified July 2026 — [Supergood Yelp report card (search summary)](https://supergood.ai/api-report-card/yelp); [App Developer Magazine (search summary)](https://appdevelopermagazine.com/yelp-fusion-api-outrageous-new-pricing/)

#### Meta (Instagram, Facebook Pages, Messenger)

- Instagram API with Instagram Login: Standard Access suffices only for accounts the developer owns or manages; Advanced Access is required when the app serves Instagram professional accounts the developer does not own, and Advanced Access requires App Review and Business Verification — [Instagram Platform overview (search summary)](https://developers.facebook.com/docs/instagram-platform/overview); [Instagram app review (search summary)](https://developers.facebook.com/docs/instagram-platform/app-review)
- App Review action items include: app loadable and testable externally, visible login button following brand guidelines, a clear use-case description, at least one successful API call, a 1024x1024 icon, Privacy Policy URL, app category and business email; the app must be connected to a business that completed Business Verification before publishing — [Instagram app review (search summary)](https://developers.facebook.com/docs/instagram-platform/app-review)
- Pages API permissions: `pages_read_engagement` (read Page content), `pages_manage_posts` (publish), `pages_messaging` (send/manage messages); Messenger Platform needs `pages_messaging`, `pages_read_engagement` and `business_management`; all permissions require App Review before app users can grant them once the app is live, and when accessing a client's Page every permission needs Advanced Access — [Pages API (search summary)](https://developers.facebook.com/documentation/pages-api); [Messenger Platform overview (search summary)](https://developers.facebook.com/documentation/business-messaging/messenger-platform/overview)
- Auth endpoints: Instagram OAuth at www.instagram.com/oauth/authorize; Facebook OAuth at www.facebook.com/v22.0/dialog/oauth; Nango also lists a Facebook "System User Token" API-key mode — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)
- No review timeline is published by Meta in the sources found (gap below).

#### Booking and scheduling

- Calendly: OAuth2 at auth.calendly.com; webhooks are routed with a user-defined signing secret; creating an app in the developer portal is self-serve (choose Web, Sandbox or Production) and yields Client ID, Client Secret and a webhook signing key; webhook subscriptions must be scoped by event family with matching read scopes (`webhooks:read`, `webhooks:write`) — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml); [Calendly scopes (search summary)](https://developer.calendly.com/docs/authentication/scopes)
- Calendly webhooks are only available on paid Calendly plans — [n8n Calendly credentials doc (search summary)](https://docs.n8n.io/integrations/builtin/credentials/calendly.md)
- A search summary stated that for newly created Calendly OAuth apps "no API access is granted until scopes are explicitly requested and approved" (unverified; the page could not be opened) — [Calendly scopes (search summary)](https://developer.calendly.com/scopes)
- Cal.com: OAuth clients are created at app.cal.com/settings/developer/oauth and start in a "pending" state until a Cal.com admin reviews and approves; the Platform API supports OAuth 2.0; the `OnboardingEmbed` React atom (package `@calcom/atoms`) lets a user create a Cal.com account, onboard and grant OAuth without leaving the host site — [Cal.com OAuth reference (search summary)](https://cal.com/docs/api-reference/v2/oauth); [Cal.com onboarding embed (search summary)](https://cal.com/docs/atoms/onboarding-embed); endpoints app.cal.com/auth/oauth2/authorize and api.cal.com/v2/auth/oauth2/token with signed webhooks — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)
- Square Bookings API went GA on 12 May 2022 in the US, UK, Canada, Australia, Spain and Japan — [Square developer blog (search summary)](https://developer.squareup.com/blog/build-with-bookings-api-now-generally-available/); it is public REST with self-serve app registration and sandbox, OAuth2 scopes and webhooks, but seller-level write access requires the merchant to be on Appointments Plus or Premium — [Supergood Square Appointments report card (search summary)](https://supergood.ai/api-report-card/square-appointments); OAuth at connect.squareup.com/oauth2 with a separate sandbox host — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)
- Acuity Scheduling (owned by Squarespace): public REST API at acuityscheduling.com/api/v1 with OAuth2 for third-party apps; OAuth app registration at acuityscheduling.com/oauth2/register; rate limit 10 requests/second and 20 concurrent connections per IP — [Nango Acuity notes](https://raw.githubusercontent.com/NangoHQ/nango/master/docs/integrations/all/acuity-scheduling.mdx); one report says OAuth2 app approval goes through Squarespace/Acuity partnerships rather than a pure self-serve portal, and some admin endpoints are gated to Powerhouse/Enterprise plans (unverified) — [Supergood Acuity report card (search summary)](https://supergood.ai/api-report-card/acuity-scheduling)
- Booksy "does not publish an open, self-serve developer API"; only unofficial reverse-engineered access exists — [Supergood Booksy docs (search summary)](https://supergood.ai/docs/booksy-api)
- Vagaro publishes a "PUBLIC - Enterprise Business API V2" at docs.vagaro.com with an access-token endpoint, five REST areas (Employee Management, Locations, Appointments, Customers, Employees) and outbound webhooks; access requires Vagaro card processing on a paid tier, a request form, and up to seven business days for approval — [Supergood Vagaro docs (search summary)](https://supergood.ai/docs/vagaro-api)

#### Restaurant reservations

- OpenTable runs a partner-gated program with no self-serve keys: the Affiliate API (restaurant data and booking deeplinks) takes 3-4 weeks for approval; Partner APIs (availability, slot locks, reservations, guest profiles, POS sync) are OAuth 2.0 and require partner application, use-case review, sandbox on approval and a formal agreement before production; expect 2-3 weeks of integration and QA after credentials — [Supergood OpenTable report card (search summary)](https://supergood.ai/api-report-card/opentable); [OpenTable partner portal FAQs (search summary)](https://dev.opentable.com/partner-portal/faqs)
- Resy has no self-serve developer portal; its Partner API (reservations, availability, guest metadata) is issued only to companies approved through a direct partnership agreement (POS, CRM, loyalty, discovery partners such as Olo); the public surface for restaurants is the embeddable "Book with Resy" button/widget; api.resy.com has been reverse-engineered but is undocumented and unsupported — [Supergood Resy report card (search summary)](https://supergood.ai/api-report-card/resy); [Resy booking button installation (search summary)](https://helpdesk.resy.com/en_us/booking-button-installation-Skx_7ueNo); [Olo partners: Resy (search summary)](https://partners.olo.com/partners/resy); [reverse-engineering writeup (search summary)](https://jonluca.substack.com/p/resy-api)

#### Zapier and Make (escape hatch)

- Zapier integrations are built on the Zapier Platform (UI or CLI) by defining authentication, triggers and actions; REST Hook triggers let Zapier subscribe to a unique URL per Zap and the app POSTs a payload to it when the event happens, avoiding polling; Create actions send POST/PUT calls to the app's API — [Zapier hook trigger docs (search summary)](https://docs.zapier.com/platform/build/hook-trigger); [Zapier integration structure (search summary)](https://docs.zapier.com/platform/quickstart/zapier-integration-structure); [Zapier trigger docs (search summary)](https://docs.zapier.com/integrations/build/trigger)
- Zapier's own account API is OAuth2 (api.zapier.com/v2/authorize) — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)
- Make custom apps: a private custom app can be built and used by its author; to offer it to all Make users the app must pass a QA code review against Make's standards, submitted from the app's Review tab with links to the service's API docs and example scenarios; once published an app cannot be unpublished and its modules cannot be deleted — [Make app review (search summary)](https://developers.make.com/custom-apps-documentation/app-review); [Make request app review (search summary)](https://developers.make.com/custom-apps-documentation/app-review/request-app-review)
- Make's own API uses an API key — [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)

#### Analytics and pixels

- Google Analytics Admin API v1beta can create a property (`properties.create`), a web data stream (`properties.dataStreams.create`) and Measurement Protocol secrets under the `analytics.edit` OAuth scope, and request an account-provisioning ticket — [GA Admin API discovery document (fetched live)](https://analyticsadmin.googleapis.com/$discovery/rest?version=v1beta)
- Cloudflare Web Analytics is "privacy-first analytics for your website without changing DNS or using Cloudflare proxy", available on all plans; setup for a non-proxied site is a JS snippet added before `</body>`; Pages projects get one-click setup — [Cloudflare Web Analytics overview](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/web-analytics/index.mdx); [Get started](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/web-analytics/get-started/index.mdx)
- Limits: 10 sites not proxied through Cloudflare, no limit for proxied sites; rules only for proxied sites (0 on Free, 5 on Pro, 20 on Business) — [Cloudflare Web Analytics limits](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/web-analytics/limits.mdx)
- The beacon is blocked by ad blockers (Brave, AdBlock Plus, DuckDuckGo); edge analytics for proxied sites cannot be blocked; the snippet can be loaded via GTM — [Cloudflare Web Analytics FAQ](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/web-analytics/faq.mdx)
- Cloudflare Zaraz natively loads Google Analytics 4, Facebook Pixel, TikTok, Google Ads, Google Conversion Linker, "Google Maps - Reserve with Google", Instagram embeds, Pinterest, Snapchat, LinkedIn Insight, HubSpot and more, plus Custom HTML/Image/HTTP tools — [Zaraz supported tools](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/zaraz/reference/supported-tools.mdx); every account gets 1,000,000 free Zaraz events per month, then $5 per additional 1,000,000; all features available on all tiers — [Zaraz pricing](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/zaraz/pricing-info.mdx)
- Astro's Partytown integration moves third-party scripts (analytics, pixels) off the main thread — [Astro Partytown guide](https://raw.githubusercontent.com/withastro/docs/main/src/content/docs/en/guides/integrations-guide/partytown.mdx)
- GTM container snippet and Meta Pixel base code installation are standard paste-an-ID snippets; official docs were not reachable (unverified in this note, but low risk).

### Inferences
- The app menu divides into three tiers of implementation effort: (1) "paste an ID" (GA4, GTM, Meta Pixel, Cloudflare Web Analytics, Resy button, Booksy link) that need no vendor relationship; (2) self-serve OAuth (Mailchimp, Constant Contact, Klaviyo, Calendly, Square, Acuity, Cal.com) that need only an app registration and token storage; (3) gated (GBP, Meta Graph, TikTok, OpenTable, Vagaro) that need an application, a verified business entity and weeks of lead time.
- Transactional email (Resend or Postmark) and SMS (Twilio) are platform infrastructure, not customer-facing apps: the engine should own one Resend/Postmark account and one Twilio account and expose "notifications" as a feature toggle, charging the business for SMS registration and usage.
- Because the Google Business Profile application itself requires a verified profile that already lists a website, the founder's own studio profile should be set up and aged now so the application can be filed; customers' profiles will be acted on through the founder's approved project via the customer's OAuth grant.
- Cloudflare Zaraz is the natural "pixel manager" for a Workers-based engine: one dashboard setting per tool, no client-side tag bloat, free at small-business volumes. It could replace the need to expose GTM to owners at all.
- Mailchimp's shrunken free tier (250 contacts) means a healthy local restaurant list outgrows Free fast; the menu should present Brevo or Klaviyo alongside Mailchimp so the owner has a free-to-cheap option, even though those use API keys.

### Gaps
- Could not open any Meta, Google developer, Klaviyo, Calendly, Cal.com, Square, OpenTable, TikTok, Zapier or Make page directly; all gating statements for those rest on search summaries of the vendor pages.
- Meta publishes no App Review SLA in the sources found; anecdotal timelines (days to weeks, multiple rejection rounds) are common but unsourced here.
- Mailchimp API availability on the 2026 Free plan is contested between two secondary sources (see conflict above).
- Places API (New) per-call pricing, Calendly plan prices, Cal.com Platform API pricing, Klaviyo and Brevo free-tier numbers could not be verified (pricing pages blocked).
- Whether Acuity OAuth registration is instant or reviewed by Squarespace partnerships is unverified.
- Whether a private (unlisted) Zapier integration can be shared with customers by invite link without review is well known in practice but no reachable source confirmed it.

## Key question 2: Which integrations matter most to a business with no website versus one switching platforms

### Takeaway
A no-website business needs Google first (profile website field, hours, reviews on the site, GA4/Cloudflare analytics) plus a contact and booking path that produces a phone call, text or booking; a switching business needs the integrations its old platform already had, which is almost always one email list, one booking or reservation tool, one or two pixels, and a Zapier escape hatch.

### Cited Findings
- The GBP application requires that the business profile already list a website, and the Business Information API can write `websiteUri`, hours and phone numbers — [Google prerequisites (search summary)](https://developers.google.com/my-business/content/prereqs); [Business Information API discovery (fetched live)](https://mybusinessbusinessinformation.googleapis.com/$discovery/rest?version=v1)
- Places API (New) can display rating, review count and up to 5 attributed reviews for any place with an API key, without GBP approval — [Places API (New) discovery (fetched live)](https://places.googleapis.com/$discovery/rest?version=v1); attribution rules — [Places policies (search summary)](https://developers.google.com/maps/documentation/places/web-service/policies)
- SMS to customers requires per-business 10DLC registration ($46 brand, $15 vetting, monthly campaign fee) — [Twilio support (search summary)](https://support.twilio.com/hc/en-us/articles/1260803965530)
- Resy's "Book with Resy" button is the public surface restaurants can install themselves; OpenTable's Affiliate API gives booking deeplinks after 3-4 weeks — [Resy report card (search summary)](https://supergood.ai/api-report-card/resy); [OpenTable report card (search summary)](https://supergood.ai/api-report-card/opentable)
- Square Bookings API supports booking widgets, availability and creating bookings with OAuth for sellers on Appointments Plus/Premium — [Supergood Square Appointments (search summary)](https://supergood.ai/api-report-card/square-appointments)
- Mailchimp Free now caps at 250 contacts and 500 sends/month — [Beehiiv blog (search summary)](https://beehiivblog.beehiiv.com/p/navigating-mailchimp-s-new-free-limits-essential-updates-for-newsletter-owners)
- Zapier REST Hook triggers fire instantly from the platform to any Zap — [Zapier hook trigger (search summary)](https://docs.zapier.com/platform/build/hook-trigger)

### Inferences
- No-website business (primary target): the integration list is short and mostly Google. The site itself is the product; the "integrations" that matter are (1) Google Business Profile website/hours sync, (2) Google reviews on the home page, (3) click-to-call/text and a contact form that emails the owner (Resend), (4) a booking or reservation link (Square/Calendly/Resy button) when the category needs it, (5) Cloudflare Web Analytics by default. Email marketing is a later upsell once the site is capturing contacts.
- Switching business (secondary target): the list is a migration checklist. Expect an existing Mailchimp/Constant Contact list, an existing scheduler (Square, Acuity, Vagaro, Booksy, Calendly), an existing reservation vendor (OpenTable/Resy), a Meta Pixel and GA4 property, and an Instagram feed widget. The dashboard's job is to re-attach those, not create them, so OAuth connect buttons for Mailchimp, Constant Contact, Klaviyo, Square, Acuity and Calendly plus paste-an-ID for pixels cover most cases.
- Instagram feed widgets are highly requested by both groups (restaurants, salons, boutiques) but sit behind Meta's Advanced Access gate; until approved, a manually curated "latest posts" block or a third-party embed is the fallback.

### Gaps
- No survey data was found quantifying which integrations US small businesses on Wix/Squarespace/GoDaddy actually use; the ranking above is inferred from vendor capabilities and the founder's segments.

## Key question 3: Which to ship first

### Takeaway
Ship the zero-gating, highest-impact set first: Cloudflare Web Analytics and GA4/Meta Pixel via Zaraz or paste-an-ID, Google reviews via Places API (New), transactional email via Resend, Mailchimp OAuth, and a booking slot (Calendly OAuth plus Square Bookings OAuth), while filing the Google Business Profile and Meta applications on day one because they take weeks.

### Cited Findings
- Cloudflare Web Analytics is free on all plans and set up by a snippet; Zaraz loads GA4, Facebook Pixel and TikTok with 1M free events/month — [Web Analytics overview](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/web-analytics/index.mdx); [Zaraz pricing](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/zaraz/pricing-info.mdx); [Zaraz supported tools](https://raw.githubusercontent.com/cloudflare/cloudflare-docs/production/src/content/docs/zaraz/reference/supported-tools.mdx)
- GA Admin API can create the property and web stream programmatically under `analytics.edit` — [GA Admin API discovery (fetched live)](https://analyticsadmin.googleapis.com/$discovery/rest?version=v1beta)
- Places API (New) returns up to 5 reviews plus rating and count with an API key — [Places API (New) discovery (fetched live)](https://places.googleapis.com/$discovery/rest?version=v1)
- Resend free tier is 3,000 emails/month with API-key auth — [Automation Atlas (search summary)](https://automationatlas.io/answers/resend-free-tier-explained-2026/); [Nango providers.yaml](https://raw.githubusercontent.com/NangoHQ/nango/master/packages/providers/providers.yaml)
- Mailchimp OAuth app registration is self-serve with immediate credentials — [CData guide (search summary)](https://cdn.cdata.com/help/CMJ/ado/pg_oauthcustomappcreate.htm)
- Calendly OAuth apps are created self-serve with webhook signing keys — [Calendly scopes (search summary)](https://developer.calendly.com/docs/authentication/scopes); Square Bookings is self-serve with sandbox, OAuth and webhooks — [Supergood Square Appointments (search summary)](https://supergood.ai/api-report-card/square-appointments)
- GBP access takes up to 14 days after a manual application and needs a 60-day-old profile — [Google FAQ (search summary)](https://developers.google.com/my-business/content/faq); [Unified.to (search summary)](https://unified.to/blog/how_to_set_up_google_business_profile_api_access_and_get_oauth_2_credentials)
- Meta Advanced Access needs App Review and Business Verification — [Instagram app review (search summary)](https://developers.facebook.com/docs/instagram-platform/app-review)
- Zapier REST Hooks and Make custom apps can be built privately before any listing review — [Zapier hook trigger (search summary)](https://docs.zapier.com/platform/build/hook-trigger); [Make app review (search summary)](https://developers.make.com/custom-apps-documentation/app-review)

### Inferences
- Recommended first six, in order: (1) Cloudflare Web Analytics plus Zaraz-managed GA4 and Meta Pixel (paste-an-ID, zero gating, every site); (2) Google reviews block via Places API (New) with compliant attribution (instant trust signal for no-website businesses); (3) Resend transactional email for contact forms, orders and bookings (platform-owned); (4) Mailchimp OAuth connect (founder already runs it in production; self-serve registration); (5) Calendly OAuth connect plus embed (services/presence variant); (6) Square Bookings OAuth (salons, barbers, trades already on Square POS; also lines up with Square payments later).
- Second wave once applications clear: Google Business Profile (website field at onboarding, hours sync, review replies, NEW_REVIEW notifications), then Meta Instagram feed and Messenger, then Constant Contact and Klaviyo OAuth (cheap to add once the OAuth connector pattern exists), then Twilio SMS with a guided 10DLC registration flow.
- Zapier escape hatch (REST hook triggers for form submission, order, booking; actions for create contact/order) should ship as a private integration in wave two; it covers every vendor the menu does not.
- Never build: Booksy (no API), Resy API (partner-only; install the button instead), Yelp Fusion ($229/month minimum for 3 excerpts is not justifiable per small business).
- Defer: OpenTable Partner API, Vagaro API, TikTok Display API; use links/buttons until a volume of restaurant or salon customers justifies the partner process.

### Gaps
- No usage data to confirm that Calendly outranks Square Bookings (or vice versa) among the founder's local service businesses; the order may flip by region and category.

## Key question 4: Which are blocked for a solo founder by app review

### Takeaway
Three gates are the real blockers: Google Business Profile (manual application that requires a 60-day-old verified profile with a website), Meta Advanced Access (App Review plus Business Verification of a legal entity), and TikTok review (manual, unguaranteed); OpenTable and Resy are partner-contract gates that a one-person studio is unlikely to clear until it has restaurant volume.

### Cited Findings
- GBP: application via contact form, email must be an owner/manager on the profile, profile verified and active 60+ days with a website, reviewed within 14 days — [Google prerequisites (search summary)](https://developers.google.com/my-business/content/prereqs); [Google FAQ (search summary)](https://developers.google.com/my-business/content/faq)
- Meta: Advanced Access requires App Review and Business Verification; the app must be connected to a business that completed Business Verification before publishing; every permission needs Advanced Access when accessing a client's Page — [Instagram app review (search summary)](https://developers.facebook.com/docs/instagram-platform/app-review); [Pages API (search summary)](https://developers.facebook.com/documentation/pages-api)
- TikTok: manual review, several days to two weeks, "no guarantees for approval" — [TikTok FAQ (search summary)](https://developers.tiktok.com/doc/getting-started-faq)
- OpenTable: partner application, use-case review, formal agreement, no self-service keys, 3-4 weeks for affiliate approval — [OpenTable report card (search summary)](https://supergood.ai/api-report-card/opentable)
- Resy: API issued only under direct partnership agreements — [Resy report card (search summary)](https://supergood.ai/api-report-card/resy)
- Vagaro: request form, paid tier with Vagaro card processing, up to 7 business days — [Supergood Vagaro docs (search summary)](https://supergood.ai/docs/vagaro-api)
- Klaviyo: unreviewed OAuth apps still install (with a warning) — not a blocker — [Klaviyo submit for review (search summary)](https://developers.klaviyo.com/en/docs/submit_your_app_for_review)
- Cal.com OAuth clients are "pending" until a Cal.com admin approves — [Cal.com OAuth (search summary)](https://cal.com/docs/api-reference/v2/oauth)
- Twilio: per-customer 10DLC brand and campaign registration with fees and vetting; an ISV must register each business — [Twilio support (search summary)](https://support.twilio.com/hc/en-us/articles/1260803965530)

### Inferences
- Meta's Business Verification is the hardest for a solo founder because it requires a registered legal entity with matching documents and a published privacy policy, plus a screencast of the OAuth flow against a test business; budget two to six weeks and expect at least one rejection round (timeline unverified).
- GBP is slow but mechanical; the founder's own business profile is the gating asset, so create and verify it immediately, list the studio website on it, and file after day 60.
- TikTok, OpenTable, Resy and Vagaro should be treated as "link out" integrations until there is customer pull; the engine can still offer a Zaraz TikTok pixel and a Resy/OpenTable button without any approval.
- Twilio SMS is not blocked by review but is blocked by paperwork per customer; the dashboard needs a guided registration wizard (EIN, address, sample messages, opt-in language) or SMS stays a premium add-on done by hand.
- Nothing in the recommended first six requires any vendor approval, which is the point.

### Gaps
- Meta's actual review duration and rejection rate for small agencies, and whether a sole proprietor without an EIN can pass Business Verification, were not confirmed.
- Whether Google will approve a GBP API application from a brand-new agency (versus an established business) is reported anecdotally as inconsistent but no authoritative source was found.
